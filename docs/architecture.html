Orbweaver architecture

Living design document. Update this page as the implementation lands. First pass is phases 1–4 as one unit; phases 5–8 follow.

Open this file in a browser (GitHub shows source, not a rendered page). Diagrams need a network connection for Mermaid from jsDelivr.

Phases 1–4 are in the tree: FastAPI gateway, in-memory or Postgres store, Anthropic tool loop with 85% compaction, web chat + STT, VS Code chat/diffs/plan mode, Telegram + cron adapters, LocalWorkspace. Snapshot CLI remains phase 6. Full CI matrix remains phase 5.

Locked decisions

Languages
Python 3.12 backend. TypeScript VS Code extension.
LLM
Anthropic Messages API. ANTHROPIC_API_KEY on the gateway only. Agent model: ORBWEAVER_MODEL (default Sonnet). Transcript classifier: ORBWEAVER_CLASSIFIER_MODEL (default Sonnet, independent). Injection probe: ORBWEAVER_INJECTION_PROBE_MODEL (default Haiku). Compaction summarizer: ORBWEAVER_COMPACT_MODEL (default Haiku). Ollama later as an optional fallback.
Memory
One hybrid store: PostgreSQL 16 + pgvector. JSON-LD graph plus embedding chunks. Standardized Memory API in front of both.
Retention
Store decay off in the first pass (λ = 0). Forget is explicit only. Pinning is first-class with a 4k token cap. Automatic eviction is phase 6.
Workspaces
Same tools, different place. LocalWorkspace (bubblewrap write confinement) for VS Code, web, Telegram, and cron. A real containerized agent is not in this pass.
Process
Gateway and channel adapters are one FastAPI process. The agent never talks to Telegram or cron.
Auth
JWT for VS Code and web chat. Telegram: bot token + allowlisted user IDs; the adapter mints an internal JWT. Rate limits per identity (120/min sliding window), shared across workers and restarts via Postgres (rate_limit_hits) or a file under ORBWEAVER_DATA_DIR (default ~/.orbweaver).
Plan mode
Orbweaver plan mode must edit HTML and Markdown. HTML with diagrams is still an editable plan, not a one-way export.
Portability
UUID schema and remap-able workspace_uri in phase 1. Snapshot CLI and off-site backups in phase 6. Secrets never travel in the pack.
Provenance
Original Python agent loop. Claude Code leak-port patterns for permissions, sandbox, and classifier (Clawd-Code, pycc, Claw Code) — no leaked TypeScript copied. VS Code diffs reimplemented from Continue APIs. Track borrowed trees in PROVENANCE.md.
Deploy
Docker Compose on a work development server. Kubernetes deferred.
Agents
One main loop plus optional subagents. Shared context via the Memory API, not a MetaGPT-style company simulation.

Target architecture

VS Code and web chat speak Orbweaver’s JWT HTTP/WebSocket API. Telegram and cron speak foreign protocols; adapters translate them into the same normalized events. Both paths hit the session router.

Shared memory

Single Postgres database orbweaver. UUID primary keys only (no serials). Sessions and agents are JSON-LD with stable @ids such as urn:orbweaver:session:<uuid>.

TableRole
entitiesJSON-LD documents; pinned. Types: Agent, Session, Task, Person, Project, Decision, Document.
triplesGraph edges (subject, predicate, object, graph_id).
chunksText + embedding + pinned; decay_score unused until phase 6.
eventsAppend-only session event log.
jobsCron / background work.
instance_metaEmbedding model, dim, schema version, instance id.
rate_limit_hitsSliding-window request timestamps when ORBWEAVER_STORE=postgres. Hashed identity keys; pruned outside the 60s window.

workspace_uri is remap-able: git remote+ref, relative file:./proj, or a named mount. Absolute laptop paths are forbidden in stored data.

Memory API

PUT /memory/entities
Upsert JSON-LD.
GET /memory/graph?id=&depth=
Neighborhood walk.
POST /memory/search
Hybrid vector kNN plus optional graph expand. Pass session_id; rewrite the query from the last N turns plus the current user text.
POST /memory/remember
Text in, embed, optional entity links.
POST /memory/pin
Always-injected working memory.
POST /memory/forget
Explicit tombstone only. No timer in the first pass.

Embeddings: local sentence-transformers. Anthropic has no first-party embeddings API.

Context across turns

The conversation is the event stream (user, assistant, tools, MemoryRecall). Do not RAG from a blank slate each turn. Pins are a hard tax; the transcript is elastic; compaction is the valve. Compaction shrinks the prompt, not the database: a compact_boundary marks the live window; dropped events stay in the session log.

Bucketv1 budget (Sonnet 200k)
Output reserve16,000 tokens
System + tool schemasMeasured, not a user budget (~12k typical)
Pinned working memory4,000 hard cap (ORBWEAVER_PINNED_TOKEN_CAP). Overflowing a pin is rejected.
Workspace skills and rules4,000 cap (ORBWEAVER_SKILLS_TOKEN_CAP). Injects root AGENTS.md / ORBWEAVER.md, .cursor/rules/*.mdc with alwaysApply: true, and optional .orbweaver/rules. Missing files are a no-op; overflow is truncated.
Event streamThe rest (~168k). Compact at ~85% full. Microcompact stubs old tool results in the prompt; oversized tool output is persisted under .orbweaver/tool-results/. Session notes (Haiku) are preferred; full compact is last resort with extractive fallback. After a boundary, recently read files are re-injected under a token cap.

New recalls land in the event stream. Dedupe by chunk id against the uncompacted window.

Agent loop

Original Python harness in backend/orbweaver/agent.py: Anthropic Messages API, TOOL_SPEC, run_tools, prompt-projection compaction in orbweaver.compact. Claude Code leak-port patterns shape permissions, bubblewrap sandboxing, the transcript classifier, the injection probe, and the compact cascade (boundary, microcompact, session notes, cached full compact). OpenHands is not a dependency. Orbweaver-specific code is memory, channels, JWT, and session routing.

Default permission mode is auto. Deny/ask/allowlist run first. In-project Write, ProposePatch, and Delete auto-allow. Bash that can run in bubblewrap auto-allows: host files are readable, writes stay in the working set (including .git), Unix sockets are allowlisted (systemd journal sockets by default; SSH_AUTH_SOCK when set), and HTTP goes through a CONNECT proxy with a domain allowlist. Sandboxed ssh uses that same proxy via ProxyCommand, a sandbox-owned ssh_config (so user-namespace ownership of /etc/ssh/ssh_config.d cannot abort OpenSSH), and read-only binds of host identity files after the ~/.ssh denyRead tmpfs — including custom names from the host IdentityFile list (host ~/.ssh/config itself stays hidden). /etc/resolv.conf is replaced with uplink nameservers so DNS still works after /run is tmpfs-hidden (systemd-resolved’s stub at 127.0.0.53 is not reachable in the sandbox, which is what broke permissions: ["full_network"] git clone). The session sandbox.json stays read-only. denyRead tmpfs overlays apply only when the path exists. Runtime sandbox limits tell the agent to ask the user before permissions: ["full_network"] or ["all"] (and the unsandboxed alias for all). Those overrides go to the classifier (ORBWEAVER_CLASSIFIER_MODEL), which returns allow, ask, or hard-deny — it asks unless a hard_deny rule matches or the user already named the override. After execution, a Haiku injection probe may prepend a warning on Read/Bash/WebFetch/WebSearch/MemorySearch output. The classifier never sees tool results. SpawnSubagent runs a nested agent_turn (depth 1) on a child Session that shares the parent workspace and Memory API; child sessions are hidden from the session list. Outbound handoff classification gates the spawn; review_subagent_return warns on the child's tool transcript before the parent sees results.

A turn allows 48 tool rounds (same for subagents). Independent tool calls should share a round. The last round is told to stop exploring and answer. If the model still returns tool_use through the cap, one more messages.create with no tools must write a user-visible answer from the transcript; only an empty conclude falls back to the old “Stopped after N tool rounds” line. Read returns a numbered window (offset / limit) with an explicit next offset instead of a silent 20k-character clip. WebSearch returns titled result URLs (DuckDuckGo HTML by default; Brave Search when ORBWEAVER_BRAVE_API_KEY is set) and is allowlisted. WebFetch strips HTML to readable text, skips persist, and says so when the page is a JavaScript shell. Grep is a regex; a\|b is treated as a|b.

v1 tools: Read (offset/limit), Write, Delete, ProposePatch (VS Code sessions only; Telegram, web, and cron use Write), Glob, Grep, ReadLints, Bash, WebFetch, WebSearch, MemorySearch, MemoryRemember, MemoryPin, MemoryForget, SpawnSubagent, AskUser, TodoWrite, ScheduleTask, SendPhoto, GenerateImage. Delete uses the same always-deny / working-set rules as Write. TodoWrite is stored on the session (todo_state event plus session JSON-LD) and re-injected after a compact boundary. ReadLints is allowlisted like Grep/Read: it runs ORBWEAVER_LINTER when set (sandboxed when bubblewrap works; falls back if bwrap cannot start), otherwise a Python AST stub.

VS Code: in auto mode in-project writes apply immediately; inline diffs are an optional overlay, not a blocking gate. Telegram and cron are headless: classifier denial limits abort the turn and notify the user. All channels use LocalWorkspace. Pushing main or force-pushing is ask-gated (headless aborts); feature-branch git push is sandboxed auto-allow. Subagents report aborted when the child hits a headless ask. The parent loop’s no-tools conclude is what the user sees if the child or parent exhausts the round cap without a natural stop.

Interfaces in phase 2: REST + WebSocket /v1/sessions/{id}/events, minimal web/ chat, POST /v1/stt (faster-whisper).

Telegram and cron

python-telegram-bot; allowlisted user IDs; voice notes go through STT. Cron: APScheduler polls a jobs table. Due jobs enqueue a synthetic user message; the host notifies Telegram and appends a cron_result session event on success or abort. Recurrence is minute/hour/day or a 5-field cron expression; one-shots are deleted after they run. Agents only request ScheduleTask.

Instance portability

Move memory and agents from a laptop to a server (or back) without rewriting IDs. Restore from backup is the same operation as migrate. Schema is phase 1; CLI is phase 6.

MovesDoes not move
entities, triples, chunks+vectors, events, jobs, agent definitions, sessions (same UUIDs), plan files, non-secret channel bindings, workspace locators ANTHROPIC_API_KEY, JWT signing keys, Telegram bot tokens, host paths, TLS, Compose .env, target Postgres password

Pack format: directory or .orb (tar+zstd). Logical JSONL dump, not pg_dump, so import can remap workspace_uri and skip secrets.

Deployment

First pass Compose: gateway, postgres, whisper (or in-process). Key from host env, never baked into the image. Bind-mount the developer workspace for LocalWorkspace; sessions still store only remap-able URIs. Sessions open pull requests into main; a green merge deploys that SHA to the live checkout.

Provenance and later rewrite

v1 goal is a working agent, not a clean IP surface. Prefer permissive upstreams. Copyleft or proprietary adapters are allowed if they unblock shipping; mark them rewrite-if-needed in PROVENANCE.md. A later rewrite pass replaces encumbered modules behind the same Memory API and session protocol.

Implementation phases

Scaffold (monorepo, Compose Postgres, Anthropic ping, PROVENANCE.md, empty snapshot/ package, local pytest smoke) happens at the start of the first pass.

  1. Phase 1 — Memory + API UUID PKs, JSON-LD, workspace_uri, Memory API, JWT, event log. Schema is snapshot-ready; no export CLI yet.
  2. Phase 2 — Agents + chat Original Python loop, leak-port permissions/sandbox/classifier, prompt-projection compaction (boundary, microcompact, session notes, Haiku summary), LocalWorkspace, web chat, STT.
  3. Phase 3 — VS Code Continue diffs, HTML+Markdown plan mode, workspace URI at session start.
  4. Phase 4 — Telegram + cron In-process adapters, LocalWorkspace for all channels. End of first pass.
  5. Phase 5 — CI only GitHub Actions: pytest on PRs into main; a green merge deploys. Later: ruff, mypy, compose integration, Playwright, vscode-test. Not memory workers. Not research agents.
  6. Phase 6 — Advanced memory and backups Optional store decay, snapshot export/import, off-site .orb packs. Restore = migrate.
  7. Phase 7 — Feature research agent Watch other harnesses, draft PRs, never auto-merge.
  8. Phase 8 — Performance-improvement agent Read Orbweaver traces, draft harness PRs, never auto-merge.
